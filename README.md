# ALOCS-1688 采购助手

一款运行在 1688 网站上的 **Chrome 浏览器扩展（Manifest V3）**，支持 **单机 / 多人共享双模式**：

- **单机模式**（默认）：装上即用，数据全部保存在本机浏览器（IndexedDB），不需要任何服务器
- **多人共享模式**（可选）：在设置页填写团队服务器地址，成员之间共享商品笔记与浏览动态，减少重复看货、重复沟通

> 打开 1688，一眼就知道这个商品自己或同事有没有看过、备注过什么。

## 功能特性

### 商品详情页浮窗（Win）

注入 `detail.1688.com/offer/*`，可拖拽、位置自动记忆，内含三个 Tab：

- **商品**：富文本笔记编辑器（自动保存）+ 团队成员笔记列表
- **供应商**：供应商笔记 + 团队成员的供应商笔记
- **数据**：累计浏览/出现统计、近 7/14/30 天趋势图（可叠加他人曲线）、浏览时段分布、**浏览时间轴**（谁在什么时候看过，滚到底自动刷新）

### 旺旺客服页侧边栏（Im）

注入千牛/旺旺客服聊天窗口，随会话切换自动更新：

- **备注**：直接在客服页给当前供应商写备注，同步进本地库
- **工厂信息**：展示供应商档案（来自旺旺「档案」Tab 的自动保存），按 **基础信息 / 工厂实力 / 服务指标** 分组——经营模式、交易方式、成立日期、主营信息、厂房面积、员工人数、生产档期、加工定制、认证信息、货描/响应/发货/回头率
- **商品**：该供应商看过的商品及其备注
- **聊天记录**：客服聊天消息实时采集入库，随时回看
- **AI**：直接分析当前会话的档案、商品、备注与聊天记录；对话与后台「我的货源 · AI」共用同一份存储，两边实时互通
- 五个页签支持**拖拽排序**（记忆布局），话术快捷输入支持置顶固定（话术库在后台设置里维护）

### AI 分析（可选，用户自带 Key）

- **后台「AI 分析」页**：整体数据洞察 + 定向检索问答
  - 整体分析：聚合统计、供应商/商品 TopN、趋势与档案分布 → 输出结论、分节要点、风险与下一步
  - 定向检索：本地 BM25 检索（MiniSearch，中文单字 + 二元分词）只把命中的档案、备注、商品与聊天片段交给模型，不发送全量数据库
  - 可选硅基流动 Rerank（`BAAI/bge-reranker-v2-m3`）：检索召回 12 → 重排 8 → 展示 6，失败自动退回 BM25
- **供应商 AI 对话**：后台「我的货源 · AI」按供应商独立多轮对话，支持快捷问题、停止、重试、复制、清空
- **客服页 AI 页签**：不离开聊天窗口就能追问当前供应商，问答会同步到后台
- **聊天噪音过滤**：系统提示、自动回复、寒暄、短句、重复内容在分析时过滤，原始记录仍完整保留

> AI 接口默认预设商汤日日新，也支持 OpenAI / DeepSeek / 任意 OpenAI 兼容地址。API Key 由用户自己填写，只保存在本机 `browser.storage.local`，不上传服务器、不写入数据库、不随多人共享同步。

### 商品卡片注入（Box）

在以下页面的每张商品卡片下方注入信息条：

- **搜索列表页**（s.1688.com / search.1688.com）
- **供应商店铺页**（店铺二级域名不固定，shop 前缀 / 自定义域名均可，React fiber 识别卡片）
- **以图搜图页 / 首页推荐**

卡片内容：

- 出现次数（列表刷出 +1）/ 浏览次数（点进详情页 +1）
- 同供应商已看商品数、近 30 天出现/浏览双图
- 多人模式下：他人浏览计数、**团队留言**卡片
- **「跳转商品」链接**：没有链接的商品也能凭商品编号一键打开详情页

### 管理后台

浏览器扩展页直接打开，免登录：

- **我的货源**：微信式左右分栏，左侧供应商列表、右侧详情
  - **全字段搜索**：供应商名、登录 ID、年限、工厂信息全部字段、工厂备注、商品标题、商品备注一处覆盖，支持多词
  - **工厂筛选**：经营模式 / 交易方式 / 认证信息 / 厂房面积档 / 员工人数档 / 资料状态，多选叠加；**级联计数**保证面板数字与列表严格一致，无内容选项自动隐藏
  - 右栏页签：备注 / 工厂信息 / 看过哪些商品 / 数据 / 聊天记录 / AI 分析（可拖拽排序）
- **AI 分析**：整体数据洞察 + 定向检索问答（见上）
- **数据概览**：浏览/出现/笔记总量统计与图表
- **存储管理**：IndexedDB 用量、容量上限、过期清理、分类自主清理、备份导出 / 导入
- **系统设置**：服务器连接（地址 / 昵称 / 共享开关 / 同步方式）、1688 页面渲染开关、**话术管理**（置顶固定）、**AI 接口**（服务商 / 地址 / Key / 模型 / 测试连接）与**重排序**配置
- **更新日志**：内置版本公告 + 手动发布记录，时间轴展示

### 多人共享与隐私

- **免注册**：填昵称即可连接，身份令牌由扩展自动生成
- **共享需明确同意**：打开「共享我的数据」开关后才上传；不共享也能查看他人数据
- **三个展示开关**：是否显示他人笔记、是否显示他人浏览数量、是否在列表页显示
- **同步方式可选**：自动同步（间隔 1 / 3 / 5 / 10 / 15 分钟）或仅手动

### 数据安全

- 数据全部存本机 IndexedDB，按扩展 ID 定位；升级 / 回滚版本 / 重载扩展**不影响数据**
- 扩展 ID 经 manifest `key` 固定，同一浏览器反复安装不会产生多个 ID、不会分裂数据
- 升级请用 [从旧版本升级](#从旧版本升级数据全部保留) 的覆盖方式；**卸载扩展**时若勾选删除数据，或直接「移除扩展」，才会清空 IndexedDB
- AI / Rerank 的 API Key 只存在本机 `browser.storage.local`，不进入数据库、不随备份导出、不参与多人共享；发给模型的只有检索命中的片段，不是全量数据

## 技术栈

| 层级 | 技术 |
|------|------|
| 扩展框架 | WXT ^0.20 |
| 前端 | Vue 3（组合式 API）+ Pinia + Element Plus + ECharts + wangEditor |
| 本地检索 | MiniSearch（BM25，中文单字 + 二元分词） |
| 本地存储 | IndexedDB（扩展 background 统一持有） |
| 共享后端 | Express + better-sqlite3（SQLite，免注册免登录） |

## 快速开始

### 安装发行版（推荐给同事 / 非开发使用）

从 [Releases](../../releases) 下载 `alocs-1688-standalone-<版本>-chrome.zip`：

1. 解压到**一个固定位置**（例如 `~/ALOCS-1688`，之后不要移动或改名）
2. 打开 `chrome://extensions`（QQ 浏览器为 `qqbrowser://extensions`），开启右上角「开发者模式」
3. 点「加载已解压的扩展程序」，选择解压出来的文件夹

> 扩展 ID 已通过 manifest `key` 固定为 `jfmjpidelkddbbfdjaopimehhconoekm`，与安装路径、版本号无关。**同一个浏览器里重复安装不会产生多个 ID，数据也不会因升级丢失。**

> **关于 CRX**：v1.2.x 起不再提供 CRX 安装包。早期打包 CRX 用的签名私钥已丢失，重新签名会让扩展 ID 变成另一个值，老用户装上去就成了「第二个插件」、看不到原有数据。zip 覆盖升级才是 ID 恒定、数据无损的方式（见下节）。

### 从旧版本升级（数据全部保留）

**核心原理**：扩展 ID 由 manifest `key` 固定为 `jfmjpidelkddbbfdjaopimehhconoekm`，本机数据（IndexedDB）按这个 ID 存放。升级只要**换掉扩展目录里的文件、不换目录名和 ID**，浏览器就认作「同一款扩展的版本更新」，笔记、聊天记录、供应商档案全部原地保留。

#### 方法 A：一键升级脚本（推荐）

从仓库 `tools/` 下载对应脚本，双击运行：

| 系统 | 文件 | 说明 |
|---|---|---|
| macOS | `一键升级-macOS.command` | 首次运行若被系统拦截，右键 → 打开 |
| Windows | `一键升级-Windows.bat` | 与 `update-windows.ps1` 放在同一目录 |

脚本会自动完成：查最新版 → 下载 → 校验扩展 ID → 备份旧目录 → 整目录覆盖 → 提示重载。全程不动数据库，末尾还会问你是否自动重启浏览器让更新生效。

同版本会直接提示「已是最新」，不会重复覆盖。

#### 方法 B：手动三步

1. 从 Releases 下载新版本 zip，解压
2. 把解压内容**覆盖**到原来的扩展文件夹（保持文件夹名不变，直接全选替换）
3. `chrome://extensions` 找到「ALOCS-1688 单机版」，点刷新 ↻（只刷新 1688 页面无效）

#### ⚠️ 千万别这么做

- **不要「先移除旧扩展再装新的」**——移除时浏览器会删掉该 ID 对应的 IndexedDB，数据就真没了
- **不要解压到新文件夹再「加载已解压」**——新路径会派生新 ID，等于装成第二个插件
- 升级前建议顺手导出一次备份：后台 → 存储管理 → 导出 JSON



### 开发自用：源码构建后原位覆盖

改完代码不想走「移除 → 重装」流程时，可以把新构建**直接覆盖进浏览器已装的扩展目录**，重载即生效，数据（IndexedDB）完全不受影响：

```bash
# 1. 构建新版本
cd wxt && npm run build

# 2. 找到已装扩展目录（扩展 ID / 版本号_0 目录名，路径因浏览器而异）
#    QQ 浏览器: ~/Library/Application Support/QQBrowser3/Default/Extensions/<扩展ID>/<版本>_0
#    Chrome:    ~/Library/Application Support/Google/Chrome/Default/Extensions/<扩展ID>/<版本>_0
#    扩展 ID 可在 chrome://extensions 页面或 <数据目录>/Default/Secure Preferences 里查到

# 3. 备份 → 整目录覆盖
cp -R "<扩展目录>" /tmp/ext-backup-$(date +%m%d-%H%M%S)
rm -rf "<扩展目录>"
cp -R wxt/.output/chrome-mv3 "<扩展目录>"

# 4. 重启浏览器（只刷新页面无效，渲染进程缓存着旧脚本）
```

三条铁律：

1. **目录名别动**（保持 `<版本>_0` 原名）：浏览器注册表里记录的就是这条路径，改名会导致扩展失效；
2. **必须整目录替换**：`assets/` 文件名带内容 hash，只丢几个文件会新旧混杂；
3. **⚠️ 如果新构建的 manifest 带 `key` 字段，覆盖后必须删掉它**：`key` 会让浏览器按公钥重算扩展 ID，与注册表里按路径派生的旧 ID 对不上，扩展会被直接禁用。`python3 -c "import json;p='<扩展目录>/manifest.json';m=json.load(open(p));m.pop('key',None);json.dump(m,open(p,'w'))"` 一行即可。带 `key` 的完整构建只用于对外发行的 CRX/ZIP。

### 从源码构建（单机模式）

```bash
cd wxt
npm install
npm run build
```

然后 Chrome 打开 `chrome://extensions` → 开启「开发者模式」→「加载已解压的扩展程序」→ 选择 `wxt/.output/chrome-mv3` 即可，数据只存在本机。

### 多人共享模式

```bash
# 1. 启动团队服务器（任选一台常开的电脑，默认 :3000）
cd server
npm install
npm run dev

# 2. 每个成员构建扩展
cd ../wxt && npm install && npm run build

# 3. 扩展加载后：管理页 → 系统设置 → 服务器连接
#    - 服务器电脑本机填 http://localhost:3000
#    - 同一局域网其他成员填 http://<服务器局域网IP>:3000，如 http://192.168.1.100:3000
#    - 填昵称 → 连接并注册 → 打开「共享我的数据」
```

> 服务器需对局域网开放 3000 端口；成员电脑需与服务器在同一局域网。
