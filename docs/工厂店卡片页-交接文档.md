> 2026-11-14。本轮回合：找工厂卡片 UI 定稿（tab/全屏富文本/三线折线图）、工厂店卡片页
> （sale.1688.com/factory/card.html）采集与注入、详情页停留时长、浏览流水合并窗口。

## 一、功能全景

### 1. 找工厂卡片 FactoryNoteCard（定稿 mock：docs/找工厂页-卡片UI-mock.html）
- 顶行：统计单行（评论/已看/浏览/聊天次·条）+ 右上「备注｜趋势」胶囊，**鼠标悬停即切**；
  默认页签由设置 `appSettings.factoryCardDefaultTab`（note/trend）决定，设置页有开关
- 备注 tab：**只读边框盒**渲染已存富文本（4 行截断）+ 全屏按钮；**只有全屏可编辑**
- 全屏：Teleport 到 body 的整屏白底覆盖层，内嵌完整 CommentInput（工具栏+保存+自动保存），
  CommentInput 新增 `hideFullscreen` prop 避免双全屏按钮；退出/保存后 reload 刷新统计
- 趋势 tab：ECharts 三线（浏览🔵/聊天🟡/商品🟢），标题行三色图例点；页签 v-show 常驻防重闪

### 2. 工厂店卡片页（sale.1688.com/factory/card.html）— box-content 分支 B2
- **进页 = 看过供应商**：`POST /suppliers/visit_records`（供应商落库+memberId、商品 upsert、
  topOfferIds 记浏览流水走 5 分钟合并窗口）
- 商品标题/图就地回填（修后台「未采集标题」；upsertProduct 只补空字段）
- 右下角 FactoryNoteCard 浮窗（可收起）；`fcPinia = createPinia()` 自建实例（勿复用页面级 pinia，TDZ）
- **相似工厂卡注入**（「为你推荐相似工厂」区块）：
  - 定位：标题叶子「为你推荐相似工厂」→ 向上自适应爬（≥3 个相关链接的祖先，**勿写死层数**）
  - 卡 = 150~500px 高包裹块；统一重构为左「主图+缩略图 2×2（.alocs-sim-imgs）」/ 中「信息压缩
    （名字 14px、正文 11px、宽度弹性）」/ 右「FactoryNoteCard 300px」
  - 广告卡（非 factory/card.html 链接）也能注入：memberId 缺省时用卡内商品链接 offerId 当代表商品；
    非 flex 结构走 `.alocs-sim-mount-abs` 绝对定位
  - **图片就绪门控**：主图 `naturalWidth===0` 时本轮跳过（防灰占位框），等重扫；URL 过滤
    `isValidImgUrl`（排除加载动图 TB1KM4iT / 1px gif）
  - **DOM 自愈幂等**：mount+图格都在→跳过；只剩 mount（React 抹了图格）→只补图格；都没有→重挂。
    不能只信 WeakSet（React 重渲染抹节点后 WeakSet 会误判已挂载）
- **工厂店商品网格注入 box 组件**：锚点用「共N个商品」链接（顶部「工厂店」页签同名，勿用标题定位）；
  商品卡容器优先「只含 1 个商品链接的父 div」，否则 `<a>` 本身；挂载后拦点击冒泡防跳转；
  mountCard + requestBatch（出现次数由 box batch 语义记，visit_records 不记出现避免双计）

### 3. 详情页停留时长
- win/App.vue：页面可见 + 最近 3 秒内有鼠标/键盘动作才计时（静止挂机暂停、切标签页不计）；
  **增量上报**（reportedDwell 只报未报过的秒数），`POST /view_records/duration` 累加到流水
- 展示：详情页面板头部 ⏱ 实时计时；后台商品行「停留 X秒」、商品抽屉「停留总时长」卡、
  供应商数据页签停留卡 + 时间轴每条时长；IM 面板数据页签停留卡 + 商品行停留

### 4. 浏览流水 5 分钟合并窗口
- `Product_browsing_history`：同商品 5 分钟内重开/刷新**复用上一条流水**（viewed_at 不变），
  返回 viewed_at 供精确回填；`/view_records/duration` 改为**累加**（客户端增量）
- visit_records 的 topOfferIds 浏览同样走合并窗口 → 时间轴不再出现刷新碎片

## 二、接口清单（localapi.js）
| 端点 | 说明 |
|---|---|
| POST /suppliers/batch_info | 新增 view_count / chat_days / chat_timeline / product_timeline（按商品首次浏览日聚合） |
| POST /view_records/duration | 停留时长增量累加（(offer_id, viewed_at) 定位） |
| POST /suppliers/visit_records | 工厂店到访：供应商+商品 upsert + 特征商品浏览（合并窗口） |
| GET /products/grouped | 商品行新增 dwell_seconds |
| GET /suppliers/stats | totals.dwell_seconds + timeline[].duration |
| GET /products/:id/stats | totals.dwell_seconds |
| GET /products/:id/view-timeline | 逐条 duration + meta total_dwell / view_total |

## 三、调试方法论（QQ 浏览器实机排障，务必按此流程）

### 工具
- **qqbrowser-skill CLI**（守护进程 ws://127.0.0.1:8765）：`browser_tab_list / browser_tab_switch
  --tabId X（不带 --sessionId） / browser_tab_reload --tabId X / browser_scroll_down --amount N /
  browser_eval_content_js --script '...' --sessionId S`。
  会话：`get_session_id` 铸 ID → `browser_attach_session --sessionId S --tabId X` 附着已有标签页；
  chrome:// 页面不可 CDP 调试（tab_not_debuggable）
- **fcDebugLog 探针**（已内置）：隔离世界的报错/里程碑写进隐藏节点 `#alocs-fc-debug`，
  主世界 `browser_eval_content_js` 读 `document.getElementById('alocs-fc-debug').textContent`
  即可拿到完整报错+堆栈（DevTools 界面翻日志很低效）
- **构建标记**：`document.documentElement.setAttribute('data-alocs-fc-build','Dx-…')`，
  eval 读属性确认页面跑的是哪一版（**每次改完务必换版本号**）
- computer-use：插件中心开关坐标点击（1280 宽光栅下 ALOCS 卡开关约 x=624,y=266）

### ⚠️ QQ 浏览器扩展更新三层缓存（血泪教训，详见记忆 qq-browser-manifest-pinning）
1. **原位覆盖安装后，页面刷新拿到的可能仍是内存里的旧内容脚本**（本次实测：reload 后
   build 标记为 null，旧挂载数据稳定复现）——**必须插件中心把扩展关-开一次**再刷新页面
2. 后台 SW 停更显示「Service Worker (无效)」，关-开后复活
3. 内容脚本改动验证流：build（换标记）→ rsync 安装 → 插件中心关-开 → `browser_tab_reload
   --tabId` → eval 读 build 标记确认 → 再验证功能

### ⚠️ TDZ 陷阱（本项目已踩两次）
box-content 的 main() 里，工厂店分支**提前 return**；排在 return 之后的 const（pinia、batchCache、
scannedOfferIds、loadedOfferIds、pageLabel）在分支的异步回调里全是暂时性死区。
**所有被工厂店流程引用的变量必须初始化在分支派发之前**。新增共享状态时放 main() 顶部。
