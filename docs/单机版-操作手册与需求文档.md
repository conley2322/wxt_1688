## 一、电脑操作（自动化工具链）

操作这台电脑的 GUI 和 QQ 浏览器，用两套工具配合。**两者的引导脚本不同，不能混用。**

### 1.1 工具分工

| 工具 | 引导方式 | 能做什么 | 用在哪 |
|------|---------|---------|--------|
| **computer-use**（MCP） | node_repl 里执行 `setupComputerUseRuntime`（computer-use-client.mjs） | 原生 GUI：扩展管理页、文件对话框、截图、键盘鼠标 | 装插件、刷新扩展、看界面效果 |
| **qqbrowser-skill**（CLI，pip 安装） | Bash 直接调命令 | 网页级：开标签、执行页面 JS、读 DOM、滚动 | 分析 1688 页面结构、验证插件注入、点击页面按钮 |
| ~~browser-use~~ | browser-client.mjs | 本环境不可用（plugin root 缺失），不要浪费时间重试 | — |

### 1.2 computer-use 标准用法

**引导代码（每次 node_repl 调用都要先执行）：**

```js
const root =
  process.env.ZCODE_CUA_PLUGIN_ROOT ??
  process.env.ZCODE_PLUGIN_ROOT ??
  process.env.CLAUDE_PLUGIN_ROOT;
const { join } = await import("node:path");
const { pathToFileURL } = await import("node:url");
const { setupComputerUseRuntime } = await import(
  pathToFileURL(join(root, "scripts", "computer-use-client.mjs")).href,
);
await setupComputerUseRuntime({ globals: globalThis });
```

**核心循环：观察 → 定位 → 操作 → 再观察**

```js
const app = await agent.computerUse.getApp({ pid: 12933 }); // QQ浏览器的 pid，用 listApps 查
const state = await app.getAXState({ disableDiffing: true }); // 拿完整元素树
// 从状态文本里用正则解析目标元素的 index，再点击：
const m = n.match(/\[(\d+)\] button 重新加载/);
await app.click(parseInt(m[1]));
```

**常用键盘操作**（`app.pressKey`）：
- `cmd+t` 新标签页、`cmd+l` 聚焦地址栏、`cmd+w` 关标签、`cmd+r` 刷新页面
- 配合 `app.typeText("网址")` + `pressKey("Return")` 完成导航

**关键经验（踩坑总结）：**

1. **元素索引会漂移**：`elements()` 返回的索引和 `getAXState` 状态树的索引可能不一致，且每次观察后树会变。**永远从最新一次状态树的文本里正则解析 index，然后立刻操作**，不要用上一次观察的缓存索引。
2. **原生文件对话框（NSOpenPanel）**：
   - 侧边栏的 cell 支持 `AXOpen` 动作（`performSecondaryAction(index, 'AXOpen')`），可以导航到 Desktop 等目录 ✓
   - 文件列表里的行，合成点击（click）无法驱动导航；但对**文件名 textfield 执行 AXOpen 可以进入该文件夹** ✓
   - 进入目标文件夹后点「选择」按钮确认
   - `Cmd+Shift+G`（前往文件夹）需要面板处于最前台，面板不在前台时会被静默忽略
3. **chrome:// 页面**（如 qqbrowser://extensions/）：qqbrowser-skill 无法自动化（不可调试），只能用 computer-use 的 AX 树操作；页面加载后 web 内容会出现在 AX 树里
4. **权限**：需要辅助功能 + 屏幕录制授权给 "ZCode Computer Use.app"；重启 ZCode 后 computer-use 工具重新可用
5. **截图验证**：`app.getScreenshot()` 返回带光栅坐标的截图，坐标只能来自当前光栅

### 1.3 qqbrowser-skill 标准用法

```bash
qqbrowser-skill serve --daemon          # 启动守护服务（浏览器重启后扩展自动重连）
qqbrowser-skill status                  # 查看连接状态（Connected clients ≥ 1 才能用）
qqbrowser-skill browser_start_session --sessionId <id> --title <名> --initialUrl <网址>
qqbrowser-skill browser_attach_session --sessionId <id> --tabId <tabId>   # 接管已开的标签
qqbrowser-skill browser_eval_content_js --sessionId <id> --script "<JS>"  # 页面内执行 JS（读 DOM 验证注入）
qqbrowser-skill browser_tab_open --url <网址>      # 开新标签（同网址会复用旧标签）
qqbrowser-skill browser_tab_switch --tabId <id>    # 切换活动标签
qqbrowser-skill browser_scroll_down --sessionId <id> --amount 3000
qqbrowser-skill browser_end_session --sessionId <id>   # 会话卡死时重建
```

**会话管理的坑：**
- `tab_owned_by_other_session` → 该标签属于另一个会话，直接 adopt 那个会话 id（如 `auto_时间戳_xxx`）
- `Debugger is not attached` → 会话状态坏了，`browser_end_session` 后重新 attach
- eval 禁止 storage API 和特权 API（chrome.runtime 等）——页面主世界没有 `browser`/`chrome` 全局
- 首次运行会自动升级并**重启 QQ 浏览器**；有新版本时命令会被阻断，先 `pip3 install --upgrade qqbrowser-skill`

## 二、QQ 浏览器经验总结

### 2.1 扩展管理

- 管理页地址：`qqbrowser://extensions/`（需要开启**开发者模式**）
- 本项目历史安装的三个扩展：

| 名称 | 版本 | ID | 状态 |
|------|------|-----|------|
| ALOCS-1688（正式版） | 0.0.0 | cppijplebacbaaepabemkdelkdpdocck | 禁用（保留） |
| ALOCS-1688（测试版） | 0.1.0 | mgjijjlbcedebnfnahekjbfedjkhfoon | 已移除 |
| **ALOCS-1688 单机版** | **0.2.0** | **illjlagdallhghmkhificghmbnnpbhmp** | **启用（当前开发）** |

- **刷新扩展**：扩展管理页点单机版卡片上的「重新载入」按钮；刷新后已打开的 1688 页面要 F5 才会注入新脚本
- **判断刷新成功**：卡片上 Service Worker 状态从"（无效）"变为有效
- **精准定位**：管理页搜索框输入 "ALOCS" 过滤，再靠版本号 + 启用开关 + ID 三重特征区分
- 单机版是"未打包扩展"，引用桌面的 `1688助手-单机版-chrome-mv3` 文件夹——**文件夹不能删/移动**，否则插件失效

### 2.2 重要踩坑记录

1. **IndexedDB 按 origin 隔离（最大的坑）**：`detail.1688.com`、`www.1688.com`、每个店铺域名、扩展页面各自一套 IndexedDB，互相看不见。解决方案：数据库只放扩展 origin（background 持有），页面脚本通过 `runtime.sendMessage` 读写
2. **MV3 onMessage 不支持 Promise 返回**：监听器必须用回调模式——`handle(...).then(sendResponse); return true`
3. **IndexedDB 建表只发生在版本升级时**：新增 objectStore 必须递增 `DB_VERSION`，否则旧库不会建新表，写入直接抛错
4. **`--load-extension` 启动参数会被剥离**：品牌版 Chromium 内核（2025+）出于安全忽略该参数——扩展能注册进配置但不运行。正式安装必须走 GUI 的「加载未打包的扩展程序」
5. **Secure Preferences 有 HMAC 保护**：直接编辑配置移除/禁用扩展可行（旧 0.1.0 就是这么移除的），但激活新扩展不行（校验失败）
6. **React 页面的注入防重**：React 重渲染会清掉注入的 DOM 但保留元素上的 `dataset` 属性——防重标记用"子元素存在性"（`.alocs-shop-mount`）而非 dataset
7. **QQ 浏览器守护进程**：浏览器退出后会被守护进程用自己的固定参数重启，`open -a --args` 的自定义参数会被丢弃；直接调二进制 `"/Applications/QQBrowser.app/Contents/MacOS/QQBrowser" --load-extension=...` 可以带参（但如上所述品牌内核会剥离）

### 2.3 风控注意事项

- 1688/淘宝对未登录访问有风控，**不要在未登录状态下用自动化大量浏览**
- 操作尽量复用用户已登录的会话和标签页；测试用商品详情页直接开（不要乱点搜索翻页）
- qqbrowser-skill 的 AI 会话会在页面上显示"AI正在网页执行任务"横幅，属正常现象

### 3.3 数据模型（IndexedDB：alocs-local，version 2）

| store | 键 | 内容 | 写入时机 |
|-------|-----|------|---------|
| profile | 'me' | 昵称、头像色 | 弹窗/个人中心修改 |
| products | offer_id | 商品（标题/主图/供应商） | 详情页浏览时自动入库 |
| view_records | 自增 | { offer_id, viewed_at } | **打开详情页 +1**（浏览次数） |
| appear_records | 自增 | { offer_id, appeared_at } | **列表页刷出商品 +1**（出现次数） |
| suppliers | name | 供应商 | 详情页浏览/评论时自动建 |
| comments | id | 商品/供应商评论 | 用户发表 |
| tags / tag_assign | id | 标签池 / 分配关系 | 用户操作 |
| updates | id | 版本更新记录 | 后台发布 |
| operation_logs | 自增 | 操作日志 | 关键写操作 |

## 四、需求信息

### 4.1 产品定位

> 打开 1688，一眼就知道哪个商品不用点进去。

ALOCS-1688 单机版：**个人单机工具**，数据全部存本机浏览器，装上即用；同时预留团队协作能力（可选配置后端同步）。

### 4.2 核心需求清单（已全部实现 ✓）

| # | 需求 | 实现 |
|---|------|------|
| 1 | 数据存浏览器，不依赖后端，装上即用 | IndexedDB + background 数据中枢 |
| 2 | 供应商店铺页/搜索页/以图搜图/首页 全部注入 | box-content 域名分流 + box-scan React fiber 扫描 |
| 3 | 商品卡片显示自己的浏览统计 | box：出现 N + 浏览 M |
| 4 | **两个浏览次数分开统计**：搜索出现（页面刷出商品 +1）与点进详情浏览（+1） | appear_records / view_records 两张流水表 |
| 5 | box1 显示折线图（X=时间，Y=次数），不与 box 内容重复 | 双折线图（出现=蓝线，浏览=金线） |
| 6 | 图型可在设置里选择（柱状/折线），不要在卡片里切换 | 系统设置 → box1 图表样式 |
| 7 | 无登录，直接进后台；默认通用头像，可改昵称 | 昵称制 + 灰色默认头像 |
| 8 | 显示存储用量；可设定上限自动清理 | 存储管理卡片（默认 100MB，流水清/创作豁免） |
| 9 | 迁移功能（对齐 time-tracker） | JSON 备份导出/导入（键值成对，自增主键不丢） |
| 10 | 更新日志带时间轴和操作人 | product_updates.created_by + 时间轴渲染 |
| 11 | 控制台全程日志可追踪 | [box] / [box:scan] / [box:shop] / [box:list] |

### 4.3 计数语义（重要）

- **出现次数**：组件渲染时（页面加载/滚动加载出这个商品）+1。同一页面会话内同一商品只计一次，刷新页面重新计。
- **浏览次数**：打开商品详情页 +1。
- 两者完全独立，box 上同时显示，box1 折线图分两条线展示近 14 天趋势。

### 4.4 未来规划（未实现）

1. **团队同步层**：设置里可配置后端地址 → 本地数据双写上传；卡片上加"获取"按钮拉取同事的记录渲染（本地优先，失败不影响单机功能）
2. 旧后端数据一键导入本地（历史数据迁移）
3. 团队版（main 分支）与单机版的功能同步策略
