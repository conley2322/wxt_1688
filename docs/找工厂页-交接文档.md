# 找工厂页 · 工厂备注功能 — 交接文档

> 更新时间：2026-11-13（第三次修订：代码基线迁移到 v1.2.2+、备注改手动保存、三栏布局）
> 分支：`standalone-local`（HEAD = `ea77f8c`，与 GitHub 最新一致）
> 主题：在 1688「找工厂」页（`s.1688.com/company/pc/factory_search.htm`）每张工厂卡片右侧注入备注组，与商品详情页「供应商」页签共用同一份数据

---

## 一、功能定稿（当前实现）

每张工厂卡片变成三栏：

```
┌──────────────┬─────────────────────┬─────────────────────────────┐
│ 图片 2×2      │ 工厂信息             │ ┌─────────┬─────────────┐  │
│ 大图缩 82px   │ 公司名(最多两行)      │ │ 备注     │ 浏览趋势     │  │
│ + 商品小图     │ 地区/资质/评分/标签   │ │ 富文本   │ 折线图       │  │
│              │ （7x24H 响应已隐藏）  │ │ +保存钮  │ 统计两行     │  │
│              │                     │ └─────────┴─────────────┘  │
└──────────────┴─────────────────────┴─────────────────────────────┘
   固定 170px     弹性压缩(flex:1 1 auto)   右栏 clamp(400px, 48%, 560px)
```

- **左栏**：图片重排为 2×2 弹性网格（大图 82px + 商品小图；无小图时保持 170px 大图），隐藏 `.right-container` 与 7x24
- **中栏**：`flex: 1 1 auto; min-width: 0`，标题 `white-space: normal` + 两行折叠，标签行允许换行 —— 目的是把宽度尽量让给右栏
- **右栏**：内部再分左右两块
  - 左：备注富文本（`CommentInput`，`showToolbar=false`，手动保存按钮）
  - 右：固定 150px —— 浏览趋势折线图（flex 撑满，约 90px）+ 两行紧凑统计（`评论 N · 已看 N` / `聊天 N 条`）
- **卡片高度不变**（210px），整卡可点跳工厂页的行为保留，但备注区内点击不得触发跳转

## 二、数据链路（与详情页「供应商」页签同源）

两处都是同一张表、同一个接口：

```
comments 表（kind='supplier'）
    ↑ GET/PUT /api/v1/suppliers/comments[/auto]?supplier_name=&member_id=&rep_offer=
    ├── 找工厂卡：FactoryNoteCard → CommentInput（target=工厂名, memberId=卡内 memberId, repOfferId=_topOfferId_）
    └── 详情页：win/pages/supplier/comment.vue → CommentInput（target=公司名, memberId=页面 memberId）
```

匹配规则（`localapi.js`）：**memberId 相同 → 名称归一化后相近（复用 `sameSupplierName`）→ 历史别名命中**，三者任一即视为同一家。

- `aliases`：两侧名字一旦连上就永久记录对方的名字，之后写法有出入也能命中
- `merged_into`：同一家因写法不同存了多条时，保留 `updated_at` 最新那条，其余打标记、读取时忽略
- `rep_offer`：工厂卡只拿到「工厂名」，与详情页「公司名」可能不是同一主体；用卡片代表商品反查 `products.supplier_name` 作为别名
- `POST /api/v1/suppliers/batch_info`：找工厂页批量取 `{my_comments, comment_count, viewed_product_count, views_timeline, chat_count}`

## 三、保存与同步机制

### 保存：手动（本次改动）
- 编辑器内改动只置 `dirty`，**不自动落库**
- 右上「保存」按钮：有改动变橙、无改动灰底但同样可点（幂等保存）；也可 ⌘/Ctrl+S
- 已移除：防抖自动保存、失焦保存、`pagehide`/`beforeunload`/卸载兜底保存

### 跨窗口同步
- 保存成功后，background 写 `storage.local.__commentChanged = { kind, target, memberId, ts }`
- 另一侧 `CommentInput` 监听 `storage.onChanged`，命中同名/同 memberId 就重读库并 `setHtml`，状态短暂显示「已同步」
- 兜底：每 2.5s 轮询该信号时间戳（个别内嵌 iframe 收不到 onChanged）
- 有 `dirty` 未保存时不接受同步覆盖，避免冲掉正在编辑的内容

## 五、防跳转守卫（重要，勿改回 window capture stopPropagation）

工厂卡整卡可点跳转是 **React 合成事件**（委托挂在页面 root，主世界），隔离世界的 `@click.stop` 无效，所以守卫放在主世界的 `box-scan.content.js`。

**当前实现（正确）**
1. window capture 上只做一件事：事件落在备注列矩形内、但 `target` 不是备注元素（被卡片透明遮罩吃掉）时才 `stopPropagation + preventDefault`；
2. 事件真在备注区内 → **放行**，让按钮/编辑器先处理；
3. 给每个 `.alocs-factory-mount` 在**冒泡阶段**挂 `stopPropagation`（覆盖 pointer/mouse/click/touch），阻止冒泡到卡片与 React root。

**历史 bug（已修）**：早期在 window capture 阶段直接 `stopPropagation()`，导致备注区里的保存按钮永远收不到 click（表现为“按钮点不了、没反应”），编辑器光标也受影响。

## 六、升级与部署注意

- **DB_VERSION 必须 ≥ 5**：IndexedDB 不能降版本。曾用低版本包覆盖安装，`open()` 直接 `VersionError`，所有本地接口全挂。v1.2.2 官方代码是 4，本分支固定 5，向后兼容 v4 的库（`chat_messages` 已存在，无需迁移）
- **部署必须保留 `manifest.json`**：构建产物的 key 与已装包不同，覆盖会改变扩展 ID → 新 origin → 数据全丢
  ```bash
  rsync -a --delete --exclude='manifest.json' wxt/.output/chrome-mv3/ \
    "$HOME/Library/Application Support/QQBrowser3/Default/Extensions/omlkcfhmicbbekplnfclgnpldachonoo/1.2.2_0/"
  ```
- **生效方式**：扩展管理页「重新加载」→ **并且刷新已打开的 1688 页面**（content script 只在页面加载时注入，不刷新仍是旧脚本）
- 扩展 ID：`omlkcfhmicbbekplnfclgnpldachonoo`（manifest key 钉死）

## 八、踩坑记录

1. **参数路由截胡固定子路径**：`/suppliers/comments/:id` 会把 `/comments/auto` 当成 id，查不到就返回 200 但一条没存。必须排除 `auto`（v1.2.2 官方代码已含此修复，本分支沿用）。
2. **隔离世界拦不住主世界事件**：涉及 React 卡片的点击拦截，一律走 MAIN world。
3. **截面守卫不能早于目标**：capture 阶段 `stopPropagation` 会掐掉目标自身的监听，必须放在冒泡阶段的容器上。
4. **IndexedDB 版本只能升**：覆盖安装前先确认 `DB_VERSION` 不小于已装版本。
5. **content script 需刷新页面**：只重载扩展不会更新已打开页面里的脚本。
